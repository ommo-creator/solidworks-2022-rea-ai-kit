# 提示词 02 · 撰写（从技术交底到可提交稿）

用途：手上只有技术交底、模型说明书、装配说明或一张系统图，要从零写出权利要求书 +
说明书 + 摘要 + 附图说明。

使用前替换占位符：

| 占位符 | 替换成 |
|---|---|
| `<DISCLOSURE>` | 技术交底 / 模型说明书 / 设计说明的路径 |
| `<FIGURE_LIST>` | 已有附图的清单（没有就写"无，需指定要出哪几张图"） |
| `<PRIOR_ART>` | 已知的最接近现有技术（可留空；留空时不得下创造性结论） |
| `<FIELD>` | 技术领域（一句话） |
| `<PROTECT>` | 申请人最想保护的那个点（一句话，说不清就先问） |

---

```text
你现在担任中国专利代理师，为一件机械结构类发明专利申请撰写申请文件。

【材料】只读 <DISCLOSURE>；附图见 <FIGURE_LIST>；已知最接近现有技术：<PRIOR_ART>。
不联网，不引入材料之外的技术特征。材料里没有的结构，不许替它补。

【先做三件事，再做撰写】
1. 一句话说清"本发明相对现有技术解决的技术问题"（不要写成"提高性能"这种空话）。
2. 列出解决该问题的**必要技术特征**清单，逐条标注它来自材料的哪一句/哪张图。
3. 指出材料里的**歧义与缺口**（尺寸缺失、装配关系不明、两个零件是否一体），
   列成待确认清单交回，不要自行假设后继续写。

【撰写要求】
一、权利要求书
- 独立权利要求：只写必要技术特征，前序部分写与最接近现有技术共有的特征，特征部分写区别特征；
  不要出现"最佳""约""优选"这类不确定用语。
- 从属权利要求：每条只增加一个（或一组强相关）附加技术特征，引用关系必须自洽；
  数量以覆盖"可能被规避的替代方案"为准，不要凑数。
- 产品权利要求里不要混入方法步骤、工艺参数、使用方式；如必须保护使用方法，
  另立方法权利要求。
- 每一条权利要求的每一个技术特征，都必须在说明书文字或附图中存在依据，
  撰写时同步标注依据位置（段号/图号）。

二、说明书
1. 技术领域：一句话定位，不要写"本发明属于机械领域"这种过宽的表述。
2. 背景技术：只写与本申请直接相关的现有技术及其缺陷，客观陈述，不贬低；
   引用对比文件时写清公开号。
3. 发明内容：技术问题 → 技术方案（与独立权利要求对应）→ 有益效果（每条效果要有依据，
   不要写"显著提高""大幅降低"而无数据或机理支撑）。
4. 附图说明：一图一句，编号连续，写清该图是什么视图、示出什么。
5. 具体实施方式：至少一个完整实施例，把装配关系写清楚（谁套在谁上、配合面在哪、
   间隙留在哪一侧）；同一部件全文用同一个名称和同一个标号。

三、摘要
不超过 300 字，写明技术方案要点与主要用途；不写商业宣传语，不写未在权利要求中出现的特征。

【输出格式】
1. 待确认清单（≤10 条，每条一行）
2. 权利要求书（1、2、3… 编号；每条后括注依据：说明书第 X 段 / 图 N）
3. 说明书（五部分，带小标题）
4. 摘要（≤300 字，单独标注字数）
5. 附图说明（一图一行）
6. 自检表：必要技术特征是否全部进独立权利要求 / 每条权项是否都有支持 / 名称与标号是否全文一致

不要输出"以下是……"这类开场白。所有数字沿用材料中的单位，全文统一。
```

---

## 撰写阶段最容易出的事

| 现象 | 后果 | 处理 |
|---|---|---|
| 独立权利要求写了非必要特征 | 保护范围被自己限死，别人少一个特征就不侵权 | 回到第 2 步，逐条问"去掉它还能解决技术问题吗" |
| 权项里的特征在说明书找不到 | 审查阶段被指"得不到支持" | 撰写时就同步标依据，找不到依据就补说明书或删该特征 |
| 说明书里同一零件三个名字 | 附图与正文对不上，盲审必挂 | 建一张"名称—标号—首次出现位置"对照表 |
| 有益效果写形容词 | 无法支撑创造性 | 每条效果配一个机理或一组数据 |
| 材料有歧义，模型自行补全 | 有可能写出"物理上装不进去"的方案 | 一律进待确认清单，不要猜 |

附录图时，用本仓库 [`../../../docs/06-line-art-figures.md`](../../../docs/06-line-art-figures.md)
的线稿配方出图：黑色线条、A4 无图框、单图单页、编号引线，直接满足专利附图的形式要求。
