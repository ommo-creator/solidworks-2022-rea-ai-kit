# 故障诊断

这里不是"常见问题列表"，而是**一次完整诊断的现场记录**：从一个看起来很吓人的现象，
一路用可测量的证据把根因钉死，并把中间排除掉的嫌疑和依据全部留下来。

| 文档 | 解决什么问题 |
|---|---|
| [`display-artifacts.md`](display-artifacts.md) | 剖切/线稿视图出现**轮廓断裂、碎线、白色块状遮挡、多重轮廓、导出图不能标注** |

---

## 为什么值得读

同一组症状，可能的解释有十几种：显卡、驱动、分辨率、模型几何、装配轻化、
显示样式、剖面封盖、相切边线、注解、图像品质、导出路径……

直觉往往会指向最贵的那个（换显卡）。但这次的实测结论是：

> 三个症状对应三个**互不相同**的原因，而且没有一个是显卡。

- **断线 / 白块 / 多重轮廓** → 显示样式选错了（用着色模式看剖切）
- **碎线** → 文档级图像品质只有 61（圆/球被折线化）
- **导出图不能用** → `SaveBMP` 读视口前缓冲，窗口不可见时导出空白帧

每一顶判断都有像素级数字支撑。读完你会拿到一套**可以套用到任何 CAD 显示问题**的
诊断顺序：先量化，再单变量，最后才动设置。

---

## 诊断用的两把尺子

### 尺子 1 · 亮度分带

把"难看"变成四个数字：

```python
dark  = (a < 128).sum()          # 真正的黑线
mid   = ((a >= 128) & (a < 190)).sum()   # 灰线 / 隐藏线
bg    = ((a >= 190) & (a < 235)).sum()   # 背景渐变 / 着色面
white = (a >= 235).sum()         # 纯白
```

同一视角、同一区域，五种显示模式各算一次，就能立刻看出"问题在模式还是在渲染"。

### 尺子 2 · 单变量差分数

每次只改一个变量，改两次回到原位，并且**必须验证回位后与基线差 0 像素**：

```python
assert diff(baseline, after_restore) == 0     # 证明测试没有污染基线
```

没有这个断言，后面所有结论都可能是在测"上一次残留的改动"。
